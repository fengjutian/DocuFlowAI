# ADR-0004：文件读写放在 workspace 服务层，打开文件即一次新的编辑会话

- 状态：已接受
- 日期：2026-11-11
- 适用范围：`editor/crates/workspace`、`editor/crates/editor-core`、`editor/crates/platform`、`editor/crates/app`

## 背景

ACP 接入（ADR-0003）之后，编辑器能跟 Agent 对话了，但存在一个让它几乎无用的
事实：**编辑器打不开文件**。启动后缓冲区永远是空的，于是：

- `Ctrl+M` 发给 Agent 的提示永远是空的（或用户在窗口里手敲的内容）；
- Agent 的会话工作目录与用户正在看的文件无关，没有真实上下文；
- 阶段 1 的退出条件「团队能够用它完成本仓库的小型日常修改」无从谈起。

阶段 0 的退出条件已经全部达成，但阶段 1 的第一个必需能力还没有。

## 决策

### 1. 新建 `workspace` crate，UI 不直接碰文件系统

架构文档的禁止事项里有一条「UI 组件直接读写文件或启动进程」。因此文件读写
收敛到 `workspace` crate 的服务接口：

```rust
pub struct Workspace { root: Option<PathBuf> }
impl Workspace {
    pub fn open(&self, path: &Path) -> Result<Document, WorkspaceError>;
    pub fn save(&self, document: &mut Document, text: &str) -> Result<(), WorkspaceError>;
    pub fn save_as(&self, document: &mut Document, path: &Path, text: &str) -> Result<(), WorkspaceError>;
}
```

`platform` 依赖这个服务，`editor-core` 完全不知道文件系统的存在。

### 2. 保存时拒绝覆盖外部改动

`Document` 除了路径和读入时的文本，还记着文件在磁盘上的**指纹**（字节长度 +
修改时间）。保存前重新读一次指纹，与打开时的不一致就**拒绝写入**并报错。

理由：编辑器打开文件到用户保存之间可能相隔很久，别的东西（另一个编辑器、
git checkout、构建脚本）都可能改过它。静默覆盖别人的改动比保存失败糟糕得多
——这与 ADR-0003 里「权限缺省为拒绝」是同一条原则：**默认动作应该是保守的**。

指纹用长度 + mtime 而不是内容哈希，是为了不把一次保存变成一次全文件读取。

### 3. 打开文件是一次新的编辑会话

`Editor::load_text` 替换缓冲区，**清空撤销/重做历史**，并把光标放到文档开头。

撤销历史必须清空：撤销到"文件还没被打开"那一刻，会恢复出从未存在于缓冲区里
的文本，那不是撤销，是回到另一个文件。清空历史让"一次打开 = 一次会话"这条
边界明确。

### 4. Agent 的上下文来自当前文件

- `Ctrl+M` 的提示是**当前缓冲区的内容**，也就是打开的文件的内容；
- ACP 会话的工作目录是**当前文件所在目录**（`session/new` 的 `cwd`），
  没有打开文件时才用 `CODEWEAVER_ACP_CWD`。

这样 Agent 拿到的是用户正在看的那个文件、站在那个目录里，而不是一个空目录。

### 5. 打开文件的方式：命令行参数

```
codeweaver-editor [file]
```

本阶段不做文件树、不做标签页、不做"打开"对话框——那些属于阶段 1 的
`workbench` 层。命令行参数是能立刻产生价值的最小入口。

## 后果

- 编辑器现在能完成一次真实的小循环：打开文件 → 编辑 → `Ctrl+S` 保存 →
  再用 `Ctrl+M` 就这个文件问 Agent。
- 状态栏显示当前路径、脏标记（`●`）和最近一条消息（保存成功/失败）。
- 只支持 UTF-8 文本；非 UTF-8 文件会明确报错而不是用替换字符糊弄过去
  （替换字符会静默损坏文件）。
- 尚未实现：多标签页、文件树、外部改动检测（只在保存时发现）、大文件模式、
  编码转换、CRLF 换行规范化。

## 被否决的方案

- **在 `editor-core` 里直接读写文件**：违反架构约束，且会让文本内核背上
  I/O 依赖。文本内核必须能在没有文件系统的情况下被测试。
- **保存时无条件覆盖**：省事，但会吃掉别人的改动。宁可让用户看到"文件已被
  修改"，也不要静默地丢掉工作。
- **用内容哈希代替指纹**：更准确，但每次保存都要把整个文件读一遍。对 100 MB
  的文件，这是把一次 O(1) 的检查变成 O(n)。长度 + mtime 足够抓住现实中的
  大多数改动。
- **一开始就做文件树和标签页**：那是 `workbench` 层的活，与"能打开一个文件"
  是两件事。先让最小循环成立。
