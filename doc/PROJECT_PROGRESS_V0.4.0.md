# CodeWeaver 项目进度与开发计划 V0.4.0

文档号：`V0.4.0`  
产品版本：`0.4.0`  
状态：开发基线  
更新日期：2026-11-12

## 1. 本期结论

V0.3.0 让运行时的取舍留在了磁盘上，V0.4.0 把同样的标准用在编辑器上：这一期之前，编辑器一次只能打开一个文件——没有文件树、没有标签页、没有脏状态，关掉一个改过的文件就是把它丢掉。

本期完成编辑器的「工作区 MVP」四件事：

1. **文件树 + 单窗口多标签**：一个窗口里可以同时打开多个文件，每个文件一个标签；文件树按需展开目录，点一下就打开文件。
2. **脏状态与关闭确认**：改过的文件在标签上带脏标记；关掉一个改过的文件会先问一句，保存 / 不保存 / 取消由用户决定，不确认就不关。
3. **外部变更检测与冲突提示**：文件在磁盘上被别人改了，编辑器会说出来，并给出「重新加载 / 保留我的修改 / 忽略」三个选择——绝不静默覆盖。
4. **语法解析移到后台**：tree-sitter 的解析从 UI 线程搬到后台线程；超过阈值的大文件进入降级模式（不高亮，但照常能编辑能保存），并有基准门禁守住这条线。

鼠标命中测试、拖拽选区、滚动与可见区定位在 V0.3.0 之前已经落地（`editor_view.rs` 的 `press`/`drag`/`scroll`/`ensure_caret_visible` 及其单元测试），本期把它们纳入验收范围并补上窗口级证据，不重复实现。

## 3. V0.4.0 开发项

### DF-0401 文件树、单窗口多标签、脏状态与关闭确认（已完成）

验收标准：

- 工作区根目录下有可展开/折叠的文件树；目录排在文件之前，同类按名称排序；`.git`、`target`、`node_modules`、`dist` 等构建目录默认不展开。
- 单窗口可以同时打开多个文件，每个文件一个标签；标签显示标题，改过的标签带脏标记。
- 切换标签保留各自的文本、光标、选区、滚动位置与撤销历史。
- 关闭一个改过的标签时弹出确认，提供保存 / 不保存 / 取消；不确认就不关闭；未修改的标签直接关闭。
- 点击标签切换标签，点击文件树里的文件打开它并激活对应标签；同一个文件不会被打开成两个标签。
- 标签模型（`workbench` crate）与缓冲区（`platform` crate）各自只负责一层，标签条与文件树的模型不依赖窗口实现。

### DF-0402 鼠标命中测试、拖拽选区、滚动与可见区定位（已完成）

验收标准：

- 点击把光标放到最近的字符上；Ctrl+点击增加一个光标。
- 按下并拖动产生选区，拖到屏幕外仍然跟手。
- 滚轮按行滚动；光标移出可见区时视图自动滚动到它。
- 命中测试、拖拽、滚动、可见区定位有单元测试覆盖，并有窗口级验收证据。

### DF-0403 外部文件变更检测与冲突提示（已完成）

验收标准：

- 打开的文件在磁盘上被修改或被删除时，编辑器检测到并提示，不静默忽略。
- 提示给出三个选择：重新加载（丢弃内存中的修改）/ 保留我的修改（写回磁盘）/ 忽略（先不管）。
- 保存时文件已被外部修改，仍然拒绝写入（既有行为保留），并把冲突交给用户处理。
- 检测是轮询式的，检测器只报告一次变化：同一个变化不会被反复提示。

### DF-0404 语法解析移到后台、大文件降级与基准门禁（已完成）

验收标准：

- tree-sitter 的解析发生在后台线程，UI 线程不再做解析。
- 后台结果按缓冲区版本校验，过期结果直接丢弃，画面上不会出现与文本不符的高亮。
- 后台请求是合并的：连续输入时只处理最新的一次请求，不积压。
- 超过阈值的文件进入降级模式：不解析、不高亮，状态说明原因；编辑、保存、查找照常可用。
- 降级阈值是一个策略对象（字节数与行数），可配置，有默认值。
- 基准门禁：大文件的解析耗时不超过预算，基准与断言都在仓库里。

### DF-0405 版本与文档号统一（已完成）

验收标准：Hermes Lab、Workspace、Tauri、原生编辑器和 ACP 握手版本统一为 `0.4.0`；本文件文档号为 `V0.4.0`。

## 5. 开发规则

1. 每个版本先更新对应版本文档，再实现文档内编号任务。
2. 产品版本必须与主进度文档号相同；跨子项目不得出现不同产品版本。
3. “完成”必须同时具备实现、自动化测试和可追溯验收结果。
4. Mock 契约通过与真实运行时通过分别记录，不互相替代。
5. 未完成项只能标记为计划、进行中或阻塞，不以界面占位视为完成。

## 6. V0.4.0 验收命令

```powershell
cd editor
cargo test --workspace
cargo bench -p codeweaver-syntax
cargo clippy --workspace --all-targets
# 窗口级证据：命中测试、拖拽选区、查找栏、语法高亮、LSP 标记
powershell -NoProfile -ExecutionPolicy Bypass -File tools\window-check.ps1
# 窗口级证据：文件树、多标签、脏标记
powershell -NoProfile -ExecutionPolicy Bypass -File tools\workbench-check.ps1

cd ..\codeweaver-hermes-lab
npm test

cd ..\codeweaver-workspace
npm run build
```

两个窗口级脚本把鼠标消息投递到编辑器自己的窗口，因此不抢走正在使用这台机器的人的鼠标；它们在 `.dev-logs/` 下留下截图与报告（该目录按既有约定不入库）。

## 7. 本期验收结果

2026-11-12 实测，命令与 §6 一致：

- **`cargo test --workspace`**：262 个用例全部通过，0 失败。分布为 platform 72、workbench 29、workspace 27、text 29（25 + 随机编辑 4）、editor-core 24、lsp 21（17 + 客户端 4）、ui 18、syntax 17、agent-acp 14（9 + 契约 5）、render 8、agent-ui 3。
- **`cargo clippy --workspace --all-targets`**：无警告。
- **`cargo bench -p codeweaver-syntax`**：8 个用例全部在预算内，门禁未触发。

  | 用例 | 中位数 | p95 | 预算 |
  |---|---|---|---|
  | parse_cold/10000-lines | 143.84 ms | 157.00 ms | 300 ms |
  | parse_warm/2000-lines | 1.46 ms | 2.17 ms | 12 ms |
  | parse_warm/10000-lines | 12.39 ms | 16.57 ms | 35 ms |
  | highlights/10000-lines/40-visible | 0.58 ms | 0.84 ms | 1 ms |
  | ui_decision/60000-lines（超限文件的判定） | 0.00 ms | 0.00 ms | 1 ms |
  | ui_handoff/20000-lines（交给后台线程的拷贝） | 0.44 ms | 0.57 ms | 16 ms |
  | background/60000-lines（后台线程直接判降级） | 1.04 ms | 18.49 ms | 100 ms |
  | background/20000-lines（后台线程的解析） | 110.04 ms | 113.57 ms | 2000 ms |

  最后四个是本期新增的门禁：前两个量的是**画图的那条线程**在大小文件上的花费（判定与拷贝），后两个量的是后台线程的往返。超限文件不再被解析，代价从「解析多久」变成「判定多久」。

两个窗口级脚本在这一轮里各自修掉了一个真问题：`window-check.ps1` 的取景坐标还停在「只有一个文件」的旧布局上（正文起点从 56/52 变成 236/78），而且把「查找栏区域」当成整块角来看——光标也是强调色，会被误认成查找栏；现在按像素坐标系逐条对齐，查找栏只认它自己那条细线。

## 8. 本期结转

- 多标签共用一个语言服务器（按首个打开的文件选择），跨语言的多标签需要为每种语言各起一个服务器——结转 V0.6.0。
- 文件树只做目录列举，不做全局搜索与项目索引——结转 V0.5.0。
- 会话恢复（重启后回到上次的标签）未做——结转 V0.5.0。
- 编辑器开着输入法（`set_ime_allowed(true)`），在装了输入法的机器上字符是输入法提交上来的，键盘消息本身不带文本；因此窗口级验收用 Delete 键改文本，而不是合成一次「打字」。这不是缺陷——真实打字走的是 `WindowEvent::Ime::Commit` 那条路，编辑器里已有对应处理——但合成按键复现不了它，验收脚本就如实改成用不需要字符的按键。
- 降级阈值现在可配（`--highlight-limit` 字节数 / `--highlight-lines` 行数），但还没有设置界面，只能从命令行给——结转 V0.5.0。
