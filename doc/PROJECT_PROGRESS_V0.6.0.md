文档号：`V0.6.0`

## 1. 本期结论

V0.5.0 把编辑器与 Agent 之间接成了一条闭环：用户挑上下文 → Agent 提改动 → 编辑器按文件/按块批准或拒绝 → 冲突交给用户选 → 每一环可追溯。

这一期补另一半：**编辑器自己也要像个开发工具**。现在它能读文件、能高亮、能补全、能跑 Agent，但「改代码」这件事仍主要靠人：格式化要另开终端跑 `cargo fmt`，重命名要全局搜索加手改，跑程序要另开一个控制台。

本期做四件事：

1. **集成终端与任务运行器**（DF-0601）：编辑器里能跑命令、看得见输出、失败时看得见原因。
2. **Git 状态、Diff、暂存与提交**（DF-0602）：改了什么、暂存什么、提交什么，都在编辑器里看得见、点得动。
3. **LSP 格式化、重命名、代码操作**（DF-0603 / DF-0604 / DF-0605）：语言服务器会的事，编辑器里按一下键就能用。
4. **最小 DAP 调试能力**（DF-0606）：断点、单步、看变量。

本期先落第三块：**DF-0603 LSP 格式化**、**DF-0604 LSP 重命名**、**DF-0605 LSP 代码操作**——语言服务器会的事，在编辑器里按一下键就能用；格式化与重命中的改动都是**一次**事务，撤销一次整体回退。

## 3. V0.6.0 开发项

### DF-0601 集成终端与任务运行器（进行中：实现完成，窗口验收待跑）

编辑器里能起一个任务、看得见它的输出、看得见它为什么失败。任务跑在**另起的进程**里：编辑器自己不被任务的死活牵连，编辑器关了，任务也停。

验收标准：

- `Ctrl+Shift+B` 起一次**构建任务**：命令按工程的清单来（`Cargo.toml` → `cargo build`，`package.json` → `npm run build`，`go.mod` → `go build`）；工程没有这些清单时，状态栏**明说**没有可以跑的命令，不静默什么都不发生。
- 任务的输出（标准输出与标准错误一起）流进窗口下方的输出面板，**一行一行**地出现，不是等它跑完才一下子冒出来。
- 任务失败时说得清：退出码是多少，输出里的最后几行是什么；输出面板自己标出「失败」。
- 任务在跑的时候再按一次键，不会起第二个任务：一次只跑一个。
- 输出面板可以关掉（`Esc`），关掉不影响任务继续跑。
- 任务的进程模型：另起的子进程，输出走管道，编辑器退出时任务被停掉。

### DF-0603 LSP 格式化（进行中）

承接自 V0.5.0 的结转项：语言服务器会格式化，编辑器却用不上，只能另开终端跑 `cargo fmt`。这一期把它接进编辑器，作为 LSP 三件套（格式化、重命名、代码操作）的第一件。

验收标准：

- 编辑器能向语言服务器要一次格式化（`textDocument/formatting`），参数里带着当前文档的 URI、缩进设置与制表符宽度；请求的是**光标所在那个文件**，服务器看到的就是用户看到的文本。
- 服务器回来的每一段编辑（`TextEdit`）都以「文本编辑」应用，而不是整篇替换；多段编辑作为**一次**事务写进缓冲区：一次撤销整体回退。
- 格式化之后，文件被标记为已修改，编辑器把新文本告诉语言服务器（否则服务器手里的文档和用户眼前的不一致，后面的诊断全是错的）。
- 没有语言服务器、服务器断开、或者服务器不给出格式化结果时，编辑器在状态栏**明说**原因，不静默什么都不发生；「没有要改的地方」也要说出来，不能让人猜是不是没生效。
- 按键是 `Alt+Shift+F`（与 VS Code 一致；`Ctrl+Shift+F` 留给「在文件里查找」）。中文输入法下带修饰键的组合可能没有名字，按虚拟键码兜底。
- 协议形状、编辑应用、按键处理都有单元测试；窗口级验收脚本证明：按一次键，文件真的被重排了，撤销能整体回退。

### DF-0604 LSP 重命名（进行中：实现完成，窗口验收待跑）

重命名会改到别的文件里，涉及跨文件的编辑与冲突。它走 DF-0603 立起来的那条管道：发请求、收回答、把回答当成**一次**事务写进缓冲区。

验收标准：

- `F2` 打开一个输入框，里头是光标处那个名字；回车确认，`Esc` 取消。名字打错了不用等服务器回答就能改。
- 编辑器向语言服务器要一次重命名（`textDocument/rename`），参数里带着当前文档的 URI、光标所在的位置和新名字；请求的是**光标所在那个文件**，服务器看到的就是用户看到的文本。
- 服务器回来的编辑按文件分派：当前文件的编辑作为**一次**事务写进缓冲区（撤销一次整体回退）；别的文件如果在编辑器里开着，也作为一次事务写进那个缓冲区；没开着的文件，改动通过工作区服务写到磁盘，磁盘上被别人改过的文件不覆盖。
- 位置对不上的文件**整个不落**：重命名落在错的地方比不重命名更糟。
- 没有语言服务器、服务器断开、服务器说这个名字改不了时，编辑器在状态栏**明说**原因，不静默什么都不发生。
- 协议形状、编辑分派、按键处理都有单元测试；窗口级验收脚本证明：按一次 `F2`，改个名字回车，文件真的改了，撤销能整体回退。

### DF-0605 LSP 代码操作（进行中：实现完成，窗口验收待跑）

代码操作要有一个列表让人挑，界面得先有形状。它走 DF-0603 立起来的那条管道：发请求、收回答、把回答当成**一次**事务写进缓冲区。

验收标准：

- `Alt+Enter`（VS Code 的「上下文操作」键；`Ctrl+.` 已经用来取消 Agent 的一轮对话）向语言服务器要一次代码操作，参数里带着当前文档的 URI 与光标所在那一行的范围；请求的是**光标所在那个文件**。
- 服务器回来的操作列成一张表让人挑：上下键换，回车确认，`Esc` 取消。没挑之前什么都不改。
- 挑中的操作带着编辑时，那份编辑按 DF-0604 的办法落地：当前文件一次事务，别的文件按开没开着分别写进缓冲区或写到磁盘。
- 挑中的操作只带命令（不带编辑）时，编辑器把命令交给服务器执行，并把结果说明白，不假装什么都没发生。
- 没有语言服务器、服务器断开、服务器说这里没有可用的操作时，编辑器在状态栏**明说**原因。
- 协议形状、操作列表、按键处理都有单元测试。

## 5. 开发规则

1. 每个版本先更新对应版本文档，再实现文档内编号任务。
2. 产品版本必须与主进度文档号相同；跨子项目不得出现不同产品版本。
3. “完成”必须同时具备实现、自动化测试和可追溯验收结果。
4. Mock 契约通过与真实运行时通过分别记录，不互相替代。
5. 未完成项只能标记为计划、进行中或阻塞，不以界面占位视为完成。
6. **开发优先，测试收口**：实现过程中不跑全量回归，也不跑窗口级脚本（它们会抢焦点、打断人）；回归集中到一轮里跑完，验收数字回填进 §6.2。

以上规则的完整版（含常用命令、代码风格、Windows 环境约束与 Git 约定）见仓库根的 [AGENTS.md](../AGENTS.md)。

### 6.3 环境约束（影响验收怎么跑）

工作区目录 `D:\github\DocuFlowAI` 带 **Low 完整性标签**，因此在仓库里构建出来的程序（编辑器、测试二进制）都以低完整性运行，而**低完整性进程不能启动中等完整性的程序**。因此窗口级验收脚本把要运行的编辑器复制到工作区之外（`%LOCALAPPDATA%\CodeWeaver\check`）再运行。

语言服务器还有一处环境事实：本机的 `rust-analyzer` 是 rustup 的代理，而 `rust-analyzer` 组件**没有装在默认工具链里**，代理直接报「Unknown binary」。真正可用的二进制在 1.98.1 工具链下（`%USERPROFILE%\.rustup\toolchains\1.98.1-x86_64-pc-windows-msvc\bin\rust-analyzer.exe`），`rustfmt` 与它在一起。编辑器本来就有 `--lsp <program>`，验收脚本用它点名这个二进制——这是环境绕行，不是产品逻辑的改动。

另外，验收用的工程必须有自己的 workspace：`cargo locate-project` 会在工程落在别的 workspace 里时报「believes it's in a workspace when it's not」，因此工程放在工作区之外，并带一张空的 `[workspace]` 表。

## 7. 本期结转

- 任务运行器现在只跑**构建任务**（`Ctrl+Shift+B`，命令由工程的清单决定）。要跑任意命令需要一个输入框和命令历史；要做真正的交互式终端还需要伪终端（PTY），Windows 上没有 POSIX 那套现成的东西。任务运行器的进程模型已经定了（另起子进程、输出走管道、编辑器退出时任务被停掉），这两件是往上加东西。
- 终端与任务运行器（DF-0601）之外的开发工具：Git（DF-0602）要定下用哪一层：命令行 `git` 还是库。命令行更省事但依赖机器上有 git，库更可控但要处理凭据；本期先不做。
- 调试（DF-0606）牵扯 DAP 协议、线程状态、变量视图，本期只把位置留着。
- 格式化现在只接了 `textDocument/formatting`；按范围格式化（只排一段）与 `onType` 格式化留到后面。
- 重命名与代码操作共用一条「服务器改文件」的管道：一次事务落进缓冲区，没开着的文件写到磁盘。**写到磁盘的那部分撤销不回来**——这是与 VS Code 一样的取舍，但要说清楚。
- 还没接 `textDocument/prepareRename`（先问服务器这个名字能不能改）、没接重命名时的 `prepareCallHierarchy` 之类；代码操作没把诊断当上下文传给服务器（`context.diagnostics` 目前是空的）。
- `Ctrl+.` 已经用来取消 Agent 的一轮对话，所以代码操作用的是 `Alt+Enter`。
