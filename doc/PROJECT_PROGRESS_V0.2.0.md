# CodeWeaver 项目进度与开发计划 V0.2.0

文档号：`V0.2.0`  
产品版本：`0.2.0`  
状态：开发基线  
更新日期：2026-11-12

## 1. 本期结论

项目已经形成三个可运行子系统：Hermes/Pi Agent 编排与审计服务、Tauri 管理控制台、Rust 原生编辑器。Phase 0 的 24 项运行时验证已完成；编辑器已具备文本事务、渲染、查找替换、语法高亮、文件读写、ACP 连接和 LSP 补全/诊断等基础能力。当前主要差距已从“技术链路是否成立”转为“产品能力是否完整、状态是否持久、编辑器是否可日常使用”。

本期完成首个产品缺口：运行时启用/禁用。禁用后的运行时仍保留在注册表和审计视图中，但不会接受新任务、不会参与自动调度，控制台可恢复启用。

## 3. V0.2.0 开发项

### DF-0201 运行时启用/禁用（已完成）

验收标准：

- `POST /api/v1/runtimes/{id}/disable` 禁用运行时；`enable` 恢复运行时。
- `GET /api/v1/runtimes` 和详情接口返回 `enabled`。
- 禁用项仍可见，但 `get/require` 不再把它交给新任务。
- 自动调度排除禁用项；健康报告明确显示 disabled，而非伪装为网络故障。
- 控制台按钮可切换状态，并在禁用时关闭健康检查入口。
- 注册表、调度器和 HTTP API 均有自动化测试。

### DF-0202 版本与文档号统一（已完成）

验收标准：Hermes Lab、Workspace、Tauri、原生编辑器和 ACP 握手版本统一为 `0.2.0`；本文件文档号为 `V0.2.0`。

## 5. 开发规则

1. 每个版本先更新对应版本文档，再实现文档内编号任务。
2. 产品版本必须与主进度文档号相同；跨子项目不得出现不同产品版本。
3. “完成”必须同时具备实现、自动化测试和可追溯验收结果。
4. Mock 契约通过与真实运行时通过分别记录，不互相替代。
5. 未完成项只能标记为计划、进行中或阻塞，不以界面占位视为完成。
