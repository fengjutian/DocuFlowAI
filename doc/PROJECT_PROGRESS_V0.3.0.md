更新日期：2026-11-12

## 1. 本期结论

V0.2.0 补上了运行时启用/禁用，但该状态只活在进程内存里：重启之后所有运行时一律回到「启用」，用户在控制台做的取舍无处可查，运行时的优先级、标签和默认归属更是从未存在过。

本期完成第一个「产品能力是否完整、状态是否持久」缺口：运行时管理可持久化。运行时的启用状态、优先级、标签和默认运行时写入磁盘配置，启动时恢复；配置损坏时服务器失败关闭并给出可定位的诊断，而不是带着半恢复的状态继续接单。

禁用语义在本期被明确为：**停止接新任务，保留存量会话**。被禁用的运行时不再接新任务、不参与自动调度，但它已经在跑的会话仍然可以继续、可以恢复——禁用是运营决策，不是断电。

## 3. V0.3.0 开发项

### DF-0301 运行时配置持久化（已完成）

验收标准：

- 运行时注册表支持 `enabled`、`priority`、`tags` 三个配置项，`defaultRuntimeId` 记录在配置文档顶层。
- 配置写入 `<dataDir>/config/runtimes.json`，采用「临时文件 + rename」原子替换，进程中断不会留下半截文件。
- 配置文档带 `version` 字段；读取时逐字段校验，非法值不得被静默修正。
- 调度器按优先级分层：只有最高优先级层内的运行时参与候选，同层内沿用原有均衡策略。
- 未配置默认运行时时，任务仍按调度策略分发；配置了默认运行时时，未点名运行时的任务落在默认运行时上。
- 配置是运行时注册表的覆盖层：注册表在运行时注册前后都能拿到同一份配置，不依赖注册顺序。

### DF-0302 启动恢复与失败关闭（已完成）

验收标准：

- 服务器启动时恢复配置，恢复后的 `GET /api/v1/runtimes` 与重启前一致。
- 配置文件缺失按「无配置」处理，服务器正常启动。
- 配置文件损坏（非法 JSON、字段类型错误、版本不支持）时服务器**失败关闭**：拒绝启动，不带半恢复状态对外服务。
- 诊断信息包含配置文件绝对路径、出错字段和出错原因，可直接定位。

### DF-0303 禁用语义：停止接新任务，保留存量会话（已完成）

验收标准：

- 禁用后该运行时不再接受新任务：点名它的任务被明确拒绝（错误信息说明「已禁用」，而不是「不存在」）。
- 禁用后自动调度排除该运行时。
- 禁用不影响存量会话：已在该运行时上执行的会话可以继续追问、可以恢复重建，恢复仍然落在同一个运行时上。
- 禁用响应回报该运行时上仍在运行的执行数量，运维据此知道禁用是立即生效还是排空生效。
- 禁用项仍保留在注册表、健康报告和控制台视图中。

### DF-0304 运行时配置审计与控制台操作记录（已完成）

验收标准：

- 每次配置变更（启用、禁用、改优先级、改标签、设默认运行时、启动恢复）写入独立的追加式审计日志，含操作者、运行时、变更前后值和时间。
- 审计日志只追加不修改，损坏行按行号报错而不是跳过。
- `GET /api/v1/runtimes/config` 返回当前配置与各运行时的生效状态；`GET /api/v1/runtimes/config/history` 返回操作记录。
- 控制台可以修改优先级、标签、默认运行时，并展示操作记录；控制台只展示服务端返回的结论，不自建状态。
- 运行时配置审计与执行 journal 分开存放：配置事件不属于任何一次执行，混进执行流水会污染执行评分与审计时间线。

### DF-0305 版本与文档号统一（已完成）

验收标准：Hermes Lab、Workspace、Tauri、原生编辑器和 ACP 握手版本统一为 `0.3.0`；本文件文档号为 `V0.3.0`。

## 5. 开发规则

1. 每个版本先更新对应版本文档，再实现文档内编号任务。
2. 产品版本必须与主进度文档号相同；跨子项目不得出现不同产品版本。
3. “完成”必须同时具备实现、自动化测试和可追溯验收结果。
4. Mock 契约通过与真实运行时通过分别记录，不互相替代。
5. 未完成项只能标记为计划、进行中或阻塞，不以界面占位视为完成。
